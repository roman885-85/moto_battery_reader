# `14-r7-4807a-4811c/` — робочі прошивки для рацій R7

Два справних пакети R7 від власника. Цінні тим, що до них **відомі правильні
відповіді**, тож на них перевіряється декодер `impres_bms.h`.

| # | Модель | Паспортна (з чипа) | Дата першого користування | Знос за показанням рації |
|---|---|---|---|---|
| 01 | PMNN4807A | 2050 мА·год (`0x008` = `0x52`) | **29.05.2024** | **100 %** |
| 02 | APLI4811C | 3100 мА·год (`0x008` = `0x7C`) | **20.06.2024** | **97 %** |

Обидві дати наш декодер відтворює **точно**:

```bash
python3 tools/decode_dump.py dumps/14-r7-4807a-4811c/files/01_PMNN4807A_2433.bin \
                             dumps/14-r7-4807a-4811c/files/01_PMNN4807A_2438.bin
```

## ⚠️ DS2438 тут лише один — від пакета 01

Власник надіслав однаковий дамп монітора для обох АКБ: у клієнті DS2438 не
перечитався між зчитуваннями. Тому файлу `02_APLI4811C_2438.bin` **немає** —
краще його не мати, ніж мати чужий.

Що DS2438 належить саме пакету 01, видно з самих даних:

| | PMNN4807A | APLI4811C |
|---|---|---|
| дата виготовлення з чипа | 2022-07-26 | 2024-05-18 |
| вік на момент зчитування | ≈1465 діб | ≈803 доби |
| ETM у цьому DS2438 | 1466 діб | 1466 діб |
| | сходиться | **неможливо** |

Пакет не міг **працювати** довше, ніж він **існує**. Саме на цьому побудовано
попередження «DS2438 не від цього АКБ» у веб-інтерфейсі та ехе-клієнті
(допуск 180 діб; на 31 рідній парі з `dumps/` перевищення сягало щонайбільше
44 діб — лічильник стартує до того, як у чип запишуть дату).

**Наслідок для зносу пакета 02.** Шунт свій у кожного АКБ, а з чужого монітора
береться `0.02604 Ом`, і знос виходить **83 %** замість справжніх 97 %. Щоб
вийшло 97 % при `CTS = 138` і паспортних 3100 мА·год, шунт цього пакета має
бути **0.0223…0.0225 Ом** (`DS2438[56..57]` ≈ `B5 08` … `CB 08`). Це передбачення
перевіряється одним перечитуванням монітора.

## Що ці дампи підтвердили

* Формат R7 (`COPYRIGHT2021` у 4807A) розбирається тією ж таблицею векторів:
  заголовок Σ ≡ `0x41`, профіль Σ ≡ `0x00`, усі 16 векторів на місці,
  15 із 16 блоків із вірною сумою — не сходиться лише блок прапорців ЗП,
  який суми й не має.
* Адреси блоків у R7 **зсунуті** відносно 4409/4488 (дати `0x1F5` замість
  `0x1EF`, калібрування `0x1C4`/`0x1CB`) — саме тому їх і треба брати з
  таблиці векторів, а не з фіксованих зсувів.
* `APLI4811C`, як і `APLI4810C`, штатно **не має** запису COPYRIGHT.
* Ключ шифрування підібрався однозначно для обох (нижній нібл `key1` = 2),
  і обидві дати збіглися з тим, що показує рація.
