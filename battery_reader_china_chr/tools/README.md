# Заставка дисплея (splash)

Стартова заставка — монохромна битмапа **64×64** у `display.h`
(`static const unsigned char ngu_xbm[] = { ... };`, розмір `NGU_W`/`NGU_H`).

Для **кольорових TFT ST7789** — окремий генератор кольорової заставки нижче.

## Замінити на своє зображення (монохромні дисплеї)

Використайте **своє** зображення (на яке маєте права):

```bash
pip install pillow
python tools/make_splash.py моя_картинка.png            # темне -> світиться
python tools/make_splash.py моя_картинка.png --invert   # інверсія
python tools/make_splash.py моя_картинка.png --dither    # напівтони (дизеринг)
```

Скрипт надрукує готовий блок `#define NGU_W/H` + `ngu_xbm[]` — вставте його у
`display.h` замість наявного масиву. Розмір лишається 64×64.

> ⚠️ Не використовуйте захищені авторським правом персонажі/лого без прав на них.

## Кольорова заставка (TFT ST7789)

Для кольорових дисплеїв — `make_color_splash.py`: генерує `custom_splash.h`
з масивом **RGB565** під вашу роздільність.

```bash
pip install pillow
python tools/make_color_splash.py logo.png -W 240 -H 240     # ST7789VW 240x240
python tools/make_color_splash.py logo.png -W 240 -H 280     # ST7789V3 240x280
python tools/make_color_splash.py logo.png -W 240 -H 320 --fit cover
python tools/make_color_splash.py logo.png --bg 001B3A       # колір фону (HEX)
```

Покладіть згенерований `custom_splash.h` у папку скетчу і ввімкніть у
`settings.h`:  `#define DISPLAY_SPLASH_CUSTOM`. Заставка малюється по центру.

## Розбір і звірка дампів (`decode_dump.py`)

Анотований розбір дампа IMPRES-чіпа й побайтова звірка «еталон vs клон».
Перевіряє ті самі інваріанти, що й прошивка: заголовок DS2433 Σ≡0x41,
TLV-записи Σ≡0x5A, дзеркало DS2438[24:50]↔DS2433[1:27], ємність (запис 0x17+21),
ETM/ICA/CCA/DCA у DS2438.

```bash
# Розбір дампа (DS2438 — необов'язковий)
python tools/decode_dump.py dump33.bin dump38.bin

# Витягти вшитий еталон із templates.h у .bin (для звірки клонів)
python tools/decode_dump.py --template PMNN4409B --out ref
#   -> ref_33.bin (512) + ref_38.bin (64)

# Побайтова звірка: «●» — розбіжність в ідентичності/калібруванні (важливо),
#                   «○» — лічильники/живі виміри (норма після скидання)
python tools/decode_dump.py ref_33.bin ref_38.bin --diff clone33.bin clone38.bin
```

## Хостові тести (`*_check.cpp`)

Збираються звичайним `g++` і ганяються **на комп'ютері**, без ESP32. Запускати
з КОРЕНЯ проєкту — частина з них читає корпус дампів у `dumps/`:

```bash
mkdir -p build
for f in tools/*_check.cpp; do
  n=$(basename "$f" _check.cpp)
  g++ -std=c++17 -I. -Itools/fake -o "build/$n" "$f" && "./build/$n" || echo "ЗБІЙ: $n"
done
```

| Тест | Що перевіряє |
|---|---|
| `battery_read_check` | посторінкове читання DS2433 на СПРАВЖНЬОМУ `BatteryReader::readBattery()` проти симульованої шини з просіданням живлення й шумом; **плюс перевірка лінії enable/підтяжки** — пін тепер моделюється (записане читається назад), тож видно, що прошивка справді розрізняє коротке на землю, коротке на живлення й справну лінію, і повертає стан піна після перевірки |
| `audit_check` | аудит змісту (чужий ключ шифрування, побиті суми блоків) на всьому корпусі `dumps/` |
| `hdrfix_check` | добудова заголовка з дзеркала DS2438 — і відсутність хибних спрацювань на 55 дампах |
| `clone_check` | відновлення за зразком китайської копії (шунт, паспортна ємність із дзеркала) |
| `charge_logic_check` | заряд на СПРАВЖНЬОМУ `charge.h`: профіль струму, регулятор шпаруватості, стартова точка понижувача, вимір струму/напруги, тепловий бюджет біполярного ключа, **контроль живлення +14 В** (класифікація, гістерезис, розрахунок на живому вимірі) і **обидві рантайм-відсічки** (`chargePsuTrip`, `chargeNoDriveTrip`) |
| `session_guard_check` | **взаємний захист заряду й розряду** на справжніх `charge.h`/`discharge.h`: зупинка однієї операції не має знімати апаратного сторожа, сигнал enable та індикацію в ІНШОЇ, що саме йде; плюс те, що скетч справді споживає прапорець перемальовки заряду й опитує живлення в спокої, а `chargeTask()` **справді викликає** обидві відсічки |

> ⚑ Чому відсічки заряду перевіряються двома різними способами. `web_server.h`
> і `display_color.h` на хості не збираються взагалі (WebServer, SPIFFS, U8g2,
> ArduinoJson), тож усе написане всередині них не покриває жоден тест
> безпосередньо. Тому логіка рішення
> живе в `charge.h` (її викликає `charge_logic_check` напряму), а `session_guard_check`
> сканує текст `web_server.h` і перевіряє, що виклики звідти нікуди не поділись.
> «Функція правильна» і «функцію хтось кличе» — різні твердження: у цьому
> проєкті вже був випадок, коли `chargeMarkDirty()` працював бездоганно, а
> `chargeConsumeDirty()` у скетчі не викликав ніхто, і заряд ніколи не оновлював
> екран.
| `reset_consistency_check` | **скидання лічильників не ламає оригінальність**: на всьому корпусі `dumps/` перевіряє, що після скидання/очистки лишаються цілими заголовок, суми TLV, дзеркало й аудит; окремо доводить на корпусі, що обнулений монітор проти повного історії DS2433 — це стан рівно тих двох дампів, які рація відкинула |
| `display_fit_check` | **текст не вилазить за плашку**: механізм переносу (`textwrap.h`) і всі написи банера помилки живлення на кожній підтримуваній панелі, зі скругленими кутами й без |
| `buzzer_dac_check` / `buzzer_ledc_check` | синтез звуку (ЦАП і ШІМ); вмикають звук ЯВНО, незалежно від `settings.h` (де він зараз вимкнений); побічно пишуть демо-`.wav` у поточну теку |

Кожен тест друкує підсумковий рядок і повертає ненульовий код при збої.

## Готовий нейтральний варіант

`tools/make_splash.py` можна нагодувати будь-якою картинкою. Приклад згенерованої
нейтральної новорічної заставки (сніжинка) — див. запит до асистента.
