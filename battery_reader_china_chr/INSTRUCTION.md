# Motorola IMPRES Battery Reader (ESP32) — повна інструкція

Пристрій для **зчитування, аналізу, редагування та програмування** чипів
акумуляторів Motorola IMPRES через веб-інтерфейс Wi-Fi і OLED/LCD-дисплей.

- **DS2433** — EEPROM 512 байт (модель, крива розряду, історія ємності,
  лічильники, блок автентифікації).
- **DS2438** — монітор батареї (напруга, струм, температура, лічильники
  заряду/розряду ICA/CCA/DCA, калібрування).

Інтерфейс українською, заставка з емблемою Національної Гвардії України.

> ⚠️ **1-Wire family codes для ЦЬОГО заліза — `DS2433_ID = 0xA3`,
> `DS2438_ID = 0xA6`** (перевірено осцилографом, у `battery_reader.h`). Це
> НЕ стандартні 0x23/0x26 з даташита. Заміна ламає зчитування — не чіпати.

---

## 1. Що потрібно

**Плата:** будь-яка ESP32 (пакет `esp32` від Espressif, перевірено на 3.3.10).
Прошивка займає ~80 % флеша — підходить схема розділів за замовчуванням.

**Бібліотеки** (Arduino Library Manager):
- `U8g2` (oliver) — монохромні OLED/LCD
- `OneWire` — шина 1-Wire
- `ArduinoJson`
- *(лише для кольорових TFT ST7789)* `Adafruit GFX Library`,
  `Adafruit ST7735 and ST7789 Library`, `Adafruit BusIO`, `U8g2_for_Adafruit_GFX`

## 2. Підключення

| Сигнал | GPIO | Константа | Примітка |
|---|---|---|---|
| 1-Wire дані (DS2433/DS2438) | **13** | `DS_PIN` | до контакту даних АКБ |
| Керування підтяжкою 1-Wire | **12** | `PULLUP_PIN` | сильний pull-up на час запису (tPROG) |
| LED зелений | **14** | `LED_GREEN_PIN` | через резистор ~330 Ом на GND |
| LED червоний | **27** | `LED_RED_PIN` | через резистор ~330 Ом на GND |
| Три кнопки на одному піні | **33** | `MENU_BTN_ADC_PIN` | аналогова драбинка, **лише ADC1** (32–39) |
| Затвор MOSFET розряду | **19** | `LOAD_PIN` | + резистор 10 кОм затвор→GND (обов'язково) |
| ШІМ заряду → **керуючий NPN** → силовий PNP | **26** | `CHARGE_PWM_PIN` | пін НЕ керує ключем напряму. Драйвер: **390 Ом** пін→база NPN (⚠️ на платі 20 кОм — замінити), **10 кОм** база NPN→GND, **120 Ом** колектор NPN→база PNP (⚠️ на платі 1 кОм — замінити), **1 кОм** база PNP→+. Ключ — PNP **B772M** |
| Вимір струму заряду | **35** | `CHARGE_ISENSE_PIN` | шунт 0.5 Ом у мінусі → **1 кОм** → пін; **лише ADC1** |
| Вимір напруги заряду | **34** | `CHARGE_VSENSE_PIN` | подільник **20к/10к** → **1 кОм** → пін; **лише ADC1** |
| Контроль живлення +14 В | **39** | `CHARGE_PSU_PIN` | подільник **68к/10к** → **1 кОм** → пін; **лише ADC1**. Допуск 12.5…16 В |

> ⚠️ Резистор **1 кОм послідовно** перед КОЖНИМ вимірювальним піном (і струму, і напруги) — струмообмеження входу АЦП. На показання він **не впливає**: вхід АЦП високоомний, струму через резистор немає, отже немає й падіння на ньому. У жодну формулу перерахунку він тому й не входить — не «виправляйте» це.

> 🔇 Звук зараз вимкнено (`BUZZER_DAC_PIN` закоментовано в `settings.h`) —
> пін віддано керованому заряду. Повертається розкоментуванням рядка.

> 🔴 **ПЕРЕД ПЕРШИМ ЗАРЯДОМ ТРЕБА ПЕРЕПАЯТИ ДВА РЕЗИСТОРИ.** Обидва — в
> обв'язці бази силового ключа, і поодинці жодна заміна нічого не дає:
>
> | Де | Стоїть | Треба | Що буде без заміни |
> |---|---|---|---|
> | пін 26 → база керуючого NPN | 20 кОм | **390 Ом** | NPN дає 0.13 мА замість 6.7 — не насичується |
> | колектор NPN → база PNP | 1 кОм | **120 Ом, 2 Вт** | струм бази 12 мА замість 106 — ключ не насичується |
>
> Наслідок в обох випадках однаковий: B772M працює в **лінійному режимі** під
> 14 В і згорає за секунди. Прошивка з нинішніми номіналами **збереться**
> (номінали плати записані окремо, як довідка), при старті надрукує
> попередження в журнал, а заряд зупинить сама відсічкою «ключ не тягне»
> приблизно за 5 секунд — але розраховувати на це як на захист не варто.

Усі піни змінюються у `settings.h`.

**1-Wire:** між лінією даних (GPIO13) і 3.3V потрібна підтяжка ~2.2…4.7 кОм.
`PULLUP_PIN` короткочасно дає сильну підтяжку під час програмування EEPROM.

## 3. Вибір дисплея

У `settings.h`, **КРОК 1** — розкоментуйте **рівно один** рядок:

```c
#define DISPLAY_SSD1306_I2C        // 0.96" 128x64 I2C (GME12864) — за замовч.
// #define DISPLAY_SH1106_I2C      // 1.3"  128x64 I2C
// #define DISPLAY_SH1107_128_I2C  // GME128128-02, 128x128 I2C (варіант SH1107)
// #define DISPLAY_SSD1327_128_I2C // GME128128-02, 128x128 I2C (варіант SSD1327)
// #define DISPLAY_ST7567_SPI      // Open-Smart 1.8" 128x64 SPI
// #define DISPLAY_PCD8544_SPI     // Nokia 5110 (PCD8544) 84x48 SPI
// --- КОЛЬОРОВІ TFT ST7789 (SPI): кольорове меню + заставка ---
// #define DISPLAY_ST7789_SPI
//   #define DISPLAY_ST7789_240X240 // ST7789VW 240x240
//   #define DISPLAY_ST7789_240X280 // ST7789V3 240x280
```

Роздільність, розкладка меню і шрифти підставляються автоматично
(на 128×128 — більший шрифт і більше рядків).

**Кольорові TFT ST7789** (240×240 VW / 240×280 V3): розкоментуйте
`DISPLAY_ST7789_SPI` + один розмір. **Типово увімкнено 240×240 (GMT130)**.
Піни SPI спільні з КРОК 2b (`SCK=18, MOSI=23, CS=5, DC=17, RST=16`),
підсвітка — `DISPLAY_BLK_PIN`
(необов'язково). Орієнтація — `DISPLAY_ST7789_ROT 0…3`, інверсія —
`DISPLAY_ST7789_INVERT`. Потрібні 4 бібліотеки Adafruit + `U8g2_for_Adafruit_GFX`
(див. розділ 1). Меню/заставка/індикатори — кольорові, реалізація у
`display_color.h` (монохромний шлях не зачіпається).

**КРОК 2a — I2C-дисплеї.** `SDA=21`, `SCL=22`, адреса `0x3C`. Працюють на
будь-яких GPIO.
- `#define DISPLAY_HW_I2C` — апаратний I2C (рендер у ~10× швидше).
  **Якщо апаратна шина не відповідає, прошивка САМА переходить на програмний
  I2C на тих самих пінах** — дисплей працює завжди; у Serial (115200) буде
  `HW I2C OK` або `SW I2C fallback`. Часта причина відмови HW I2C — слабкі
  підтяжки: поставте зовнішні **4.7 кОм** з SDA і SCL на 3.3V.
- `#define DISPLAY_I2C_KHZ 0` — частота шини, `0` = АВТО (безпечний максимум
  з драйвера: SSD1306/SH1106/SH1107 — 400 кГц, SSD1327 — лише 100 кГц).

**КРОК 2b — SPI-дисплеї** (ST7567 / Nokia 5110 / ST7789). Апаратний SPI ESP32:
`SCK=18`, `MOSI=23` (до CLK/DIN/SDA), керуючі `CS=5`, `DC=17`, `RST=16`.

> ⚑ **На модулях ST7789 240x240 (GMT130) виводу CS фізично немає** — на
> гребінку виходять лише `GND / VCC / SCL / SDA / RES / DC / BLK`, а GPIO5
> нікуди не підключений. Рядок `DISPLAY_CS_PIN` попри це **заданий**: смикати
> непід'єднаний пін електрично безкоштовно, а режим «CS немає» (`-1`)
> спирається на внутрішню гілку бібліотеки, реалізовану в різних версіях
> `Adafruit_SPITFT` по-різному. Заданий пін працює скрізь.
> Закоментувати рядок можна — тоді GPIO5 звільняється, але шину SPI не можна
> буде ділити ні з чим.
> Єдина умова: шина SPI має лишатись тільки під дисплеєм (без CS він слухає її
> постійно). Перевірка при збірці стежить, щоб `GPIO18/23` не зайняли чимось
> іншим.
- `DISPLAY_ST7567_XOFF` (за замовч. 4) — зсув картинки, підберіть 0…4, якщо
  зсунута.
- `#define DISPLAY_CONTRAST 128` (опційно) — ручний контраст (для ST7567
  більше = темніше, типово 30…90).

> GME128128-02 буває на SH1107 **або** SSD1327 — якщо картинка спотворена,
> перемкніть між цими двома опціями. Якщо обрано **SSD1327**, а екран пустий
> чи спотворений — панелі бувають з різним контролером-remap: у `settings.h`
> розкоментуйте один із `SSD1327_WS` / `SSD1327_EA` / `SSD1327_ZJY`
> (за замовч. MIDAS). Також допомагає задати `DISPLAY_CONTRAST` (для SSD1327
> усталено 0x7F). Активний дисплей і частоту I2C видно в Serial при старті. На Nokia 5110 (84×48) частина нижніх
> рядків не влазить — усі дані краще дивитись у вебі.

### Якщо екран лишається чорним

**Спершу — дві найчастіші причини саме на панелях без виводу CS** (як
GMT130-V1.0). Обидві тепер налаштовуються в `settings.h`, і типові значення вже
виставлені під цей модуль.

> ✅ На цьому пристрої чорний екран був саме через **режим SPI**: типові
> значення нижче вже правильні, і окремо налаштовувати нічого не треба.
> Розділ лишається для інших панелей і для випадку, якщо колись знадобиться
> знову.


| Причина | Константа | Типово | Що робити |
|---|---|---|---|
| не той **режим SPI** ← *саме це й було тут* | `DISPLAY_ST7789_SPI_MODE` | **3** для 240×240 | спробуйте `0` — і навпаки |
| завелика **частота SPI** | `DISPLAY_ST7789_SPI_HZ` | 24 МГц | знижуйте: `10000000`, потім `8000000` |

Режим важливий саме через відсутність CS: він припаяний до землі, контролер
вибраний **завжди** і межу посилки визначає за станом такту в спокої — а він у
режимів 0 і 3 різний. З «не тим» режимом панель приймає біти зі зсувом, жодної
команди не впізнає й лишається чорною, хоч усе припаяно правильно.

Частота — класика дротів-перемичок: на доріжках плати десятки МГц працюють, на
40-сантиметрових перемичках дають «сніг» або той самий чорний екран.

**Далі — розрізнити підсвітку й обмін.** Сама по собі чорнота нічого не каже:
однаково виглядають **згасла підсвітка** і **мовчазна шина SPI**. Розкоментуйте
в `settings.h`:

```c
#define DISPLAY_ST7789_SELFTEST
```

Після прошивки дисплей на 3 секунди заллється чистими кольорами при повній
підсвітці, а кроки продублюються в Serial (115200):

| Що бачите | Висновок | Куди дивитись |
|---|---|---|
| кольори змінюються | підсвітка й обмін **справні** | верстка, орієнтація `DISPLAY_ST7789_ROT`, оффсети |
| екран світлий, але кольорів немає | підсвітка є, **обміну немає** | SDA→GPIO23, SCL→GPIO18, DC→17, RES→16, живлення панелі, CS |
| екран лишається темним | **немає підсвітки** | BLK→GPIO4 і її живлення |

У журналі при старті прошивка друкує повну конфігурацію екрана:

```
DISPLAY: ST7789 240x240 (panel 240x240) color, rot=1, SPI mode=3 24.0 МГц, DC=17 RST=16 CS=5 BLK=4
```

Якщо цього рядка немає взагалі — до ініціалізації дисплея справа не дійшла,
причина раніша (живлення, збірка, паніка при старті — дивіться `RESET REASON`
у тому ж журналі).

## 4. Прошивка

1. Оберіть плату ESP32 і порт (*Tools → Board / Port*).
2. Скомпілюйте та завантажте скетч `motorola-battery-reader-web.ino`.
3. **Завантажте файли у SPIFFS** — вміст теки `data/` (`index.html`,
   `logo.png`) через *Tools → ESP32 Sketch Data Upload* (плагін ESP32FS для
   Arduino IDE 1.8.x). **Без цього кроку веб-сторінка не відкриється.**
   - Помилка `No port specified` = не вибрано порт у *Tools → Port* або
     відкритий Serial Monitor (закрийте його).

---

## 5. Перше під'єднання

1. Підключіться до Wi-Fi **`BatteryReader_moto`**, пароль **`12345678`**.
2. **Captive-portal:** телефон/ПК сам запропонує «Вхід у мережу» і відкриє
   сторінку. Якщо ні — відкрийте `http://192.168.4.1`.
3. Пароль на операції **прибрано** — запис/скидання доступні напряму (керування
   локальним доступом до пристрою).

## 6. Веб-інтерфейс

### Вкладка «Огляд»
Заряд (%, з джерелом ICA/напруга), напруга, температура, модель, ємність,
знос, кількість циклів заряд/розряд, справжність (OK / РИЗИК + причина).
Кнопки: **Зчитати АКБ**, **Оновити**.

### Вкладка «Дані»
- Модель і серійний номер чипа (лазерний ROM DS2438).
- DS2438: напруга, струм (мА), температура, **Залишок (ICA)**,
  **Заряджено (CCA)**, **Розряджено (DCA)** — усе в мА·год і циклах,
  з сирим значенням у дужках.
- Повні hex-дампи DS2438 (64 Б) і DS2433 (512 Б).

### Вкладка «Прошивка»
1. **Зчитування та резервна копія** — зчитати АКБ, завантажити дампи
   DS2433/DS2438 у `.bin`. **Завжди робіть бекап перед записом.**
2. **Запис / відновлення прошивки** — записати `.bin` (512 Б) у DS2433.
   Це і є відновлення повністю стертої АКБ: запис **завідомо справного**
   дампа тієї ж моделі.
3. **Запис DS2438** — записати `.bin` (64 Б) у монітор.
4. **♻️ Скидання для рекалібрування** — обнуляє лічильники заряду/розряду
   (CCA/DCA/таймер) і знос (ємність→100 %), перераховує суми, пише в чіп.
   Далі калібруйте АКБ на **оригінальному** IMPRES-ЗП.
5. **🔋 Змінити залишкову ємність (мА·год)** — рівень заряду записується в
   регістр ICA монітора DS2438 (`ICA = мА·год ÷ (0.4882/Rsense)`). На головному
   екрані пристрою та в огляді (веб/USB) заряд показано в **мА·год** (відсоток —
   дрібним рядком). Окремо є **🔧 знос/здоров'я %** (0–100 %, запис 0x17 + сума).
6. **🛠 Ремонт цілісності** — перерахунок контрольної суми заголовка
   (Σ≡0x41), сум відомих записів (Σ≡0x5A) і відновлення дзеркала калібрування
   з уцілілого DS2438 (`DS2438[24:50]→DS2433[1:27]`). Статус показано:
   заголовок ✅/❌, дзеркало ✅/❌.
7. **🧹 Очистити (крім критичних даних)** — стирає ВСІ дані використання/
   історії/статистики (лічильники, знос, таблиці 0x16), зберігаючи модель,
   серійний/ID, криву калібрування, блок автентифікації та дзеркало
   DS2438↔DS2433. Контрольні суми перераховуються. Доступно і з меню дисплея
   (сторінка «Дії» → Очистка).
8. **🔥 ПОВНЕ стирання DS2433 (крайній випадок)** — стирає ВЕСЬ чіп DS2433 у
   0xFF, разом з моделлю/серійним/ID/калібруванням. Після цього АКБ не працює,
   доки не запишете еталонний дамп тієї ж моделі. DS2438 не чіпається (з нього
   потім відновиться калібрування). Веб/USB (небезпечна зона) і меню дисплея.
9. **✏️ Редактор байтів (експертний)** — правка будь-яких байт DS2433/DS2438
   прямо в браузері. «Автовиправлення» перераховує суму заголовка DS2433 і
   тримає дзеркало узгодженим. Кнопка «Завантажити» підтягує поточний дамп.

> Вкладку «Прошивка» згруповано: **Резервна копія** → **Обслуговування**
> (безпечно для ідентичності) → **Небезпечна зона** (незворотні операції).
> Спочатку резервна копія; незворотні дії — зі свідомим підтвердженням.

### Вкладка «🧙 Майстер»
Автоматичне відновлення: **аналіз** стану → перелік **проблем** → **план** дій
→ покрокове **виконання**. Багатоетапні сценарії з IMPRES-ЗП продовжуються після
повернення АКБ (стан — у журналі ESP32 за серійником). Панель **🗂 Збережені
відновлення** показує заплановані дії й дозволяє їх видалити.

### Оформлення
Веб-інтерфейс — військовий стиль (хакі/олива/«краповий») з емблемою НГУ. На
кольоровому дисплеї — плавна заставка, плавучий градієнт заповнення батареї й
червоний «світлофільтр» при помилці.

## 7. Керування на пристрої (кнопки)

Сторінки меню (перелистування кнопкою «Вперед»):
1. Головна (заряд + статус) 2. Модель / серійний 3. Дані батареї (DS2438)
4. Стан АКБ (ємність/знос/цикли/справжність) 5. Дамп DS2438 (hex)
6. Дамп DS2433 (hex) 7. Дії (Скидання/Ремонт/Очистка/Стерти/Рекалібр./Новий/Відновити)
8. 🧙 Майстер відновлення.

**Режим 2 кнопок** (за замовчуванням):
- **«Вперед» коротко** — наступна сторінка; **довго (0.8 с)** — зчитати АКБ.
- **«Назад» коротко** — попередня сторінка; на **«Діях»** — вибір операції;
  на **«Майстрі»** — аналіз.
- **«Назад» довго (0.8 с)** на «Діях» — **виконати** обрану операцію; на
  «Майстрі» — наступний крок.

**Режим 3 кнопок** (`MENU_BTN3_PIN` у `settings.h`): «Вперед»/«Назад» — **ЛИШЕ
навігація**, уся дія — на третій кнопці «OK / Дія»:
- **головна:** коротко = зчитати АКБ, довго = у «Майстер»;
- **«Дії»:** коротко = наступна операція, довго = ВИКОНАТИ;
- **«Майстер»:** коротко = аналіз, довго = наступний крок;
- інші сторінки: коротко = у «Майстер», довго = на головну.

Підказки керування внизу екрана підлаштовуються під режим (2 чи 3 кнопки).

### Якщо читання пакета не працює («нема чіпа»)

`GPIO12` — це не лише підтяжка 1-Wire, а й **enable самого акумулятора**: доки
він не піднятий, пакет мовчить, і читання не вдасться, хай яким справним буде
все інше.

> 🔴 **Якщо читання зламалось саме ПІСЛЯ переробки заряду**, перевірте два
> місця — переробка зачепила обидва:
> 1. **GPIO32** — колишній `CHARGE_PIN` (enable силового каскаду). Переробка
>    його прибрала, і пін лишився висіти входом, хоча раніше його опускали в
>    LOW найпершим рядком `setup()`. Якщо доріжка на платі ціла, на вході
>    чужої схеми з'явився невизначений рівень. Прошивка знову утримує його в
>    LOW (`CHARGE_LEGACY_EN_PIN` у `settings.h`).
> 2. **Шунт 0.5 Ом у мінусовому проводі** — він розділив «мінус» пакета й
>    землю ESP32. Чипи DS2433/DS2438 всередині пакета відлічують свою землю
>    від мінусової клеми, а підтяжка й лінія даних — від землі ESP32. Якщо
>    спільної землі не лишилось, шина мовчить так само, як із порожнім
>    роз'ємом. Перевірка нижче це називає прямо.

Прошивка тепер перевіряє цю лінію сама — піднімає, читає рівень назад, опускає,
читає ще раз (на ESP32 вхідний буфер вихідного піна лишається увімкненим, тож
видно **реальний** стан виводу, а не те, що записали). Результат у журналі при
старті:

```
1-Wire: пін даних 13, enable/підтяжка 12
  керуючий пін: лінія enable/підтяжки справна
  лінія даних: лінія даних керується підтяжкою правильно
```

Два рядки, і вони про різне. **Керуючий пін** — чи піднімається сам GPIO12.
**Лінія даних** — чи піднімається від нього GPIO13, тобто чи працює підтяжка
насправді. Саме другий рядок відповідає на скаргу «підтяжки немає»: керуючий
пін може бути ідеально справним, а підтяжка не доходити.

Якщо лінія несправна, замість «ПОМИЛКА: нема чіпа» на екрані з'явиться
**«ПОМИЛКА: підтяжка (GPIO12)»**, а в журналі — що саме: не піднімається
(коротке на землю, надто низькоомна підтяжка вниз, пробитий ключ) чи не
опускається (коротке на живлення). Це важлива різниця: «нема чіпа» звинувачує
пакет, а причина може бути у власній обв'язці.

> ⚠️ **GPIO12 — strapping-пін (MTDI).** Рівнем на ньому **в момент скидання**
> ESP32 вибирає напругу живлення флеш-пам'яті: HIGH означає «флеш 1.8 В», а на
> більшості модулів вона 3.3 В — і плата просто не завантажиться. Тому:
> * **жодної зовнішньої підтяжки вгору** на самому GPIO12;
> * підтяжка вниз припустима й навіть корисна, але не занадто низькоомна —
>   пін мусить лишатись здатним підняти лінію;
> * якщо обв'язку доведеться переробляти, вільний **GPIO32** підходить краще:
>   повноцінний вхід/вихід без strapping-обмежень.

### Оповіщення про несправне живлення

Без правильного блока живлення заряд не піде взагалі, тому помилка показується
**одночасно на чотирьох поверхнях**, і скрізь із блиманням:

| Де | Як виглядає |
|---|---|
| **екран пристрою** | сторінка помилки з'являється **сама**: **блимаюча червона плашка** з нерухомим текстом усередині — «НЕМАЄ ЖИВЛЕННЯ» / «НАПРУГА ЗАНИЖЕНА» / «НАПРУГА ЗАВИЩЕНА», під ним пояснення, виміряна напруга й **потрібний номінал** («треба 14 В», допуск у дужках) |
| **світлодіод** | постійний код: два червоних спалахи, пауза |
| **веб-інтерфейс** | блимаюча червона смуга вгорі **будь-якої** вкладки |
| **USB-клієнт** (HTML і Python) | така сама блимаюча смуга над вкладками |

Сторінка на екрані **знімається будь-якою кнопкою** — і це навмисно: пристрій
уміє не лише заряджати, читати й правити пам'ять пакета можна взагалі без блока
живлення. Якби сторінка трималась намертво, відсутній блок робив би непридатним
увесь прилад. Після зняття лишаються «`!`» у шапці й код на світлодіоді, а якщо
несправність зміниться на іншу (наприклад, «занижено» → «немає») — сторінка
з'явиться знову.

Блимає **плашка**, а не текст: слова стоять нерухомо й читаються в обидві
фази. Сам рух потрібен — статичну червону смугу за хвилину перестаєш помічати,
а рухома лишається видимою боковим зором. Період — `DISPLAY_PSU_BLINK_MS`
(типово 500 мс). У браузері блимання вимикається системним налаштуванням
«зменшити рух» — смуга з текстом при цьому лишається.

> ⚡ **Код несправності живлення** (`LED_FAULT`) відрізняється від звичайної
> помилки навмисно: «помилка» — це одноразовий сигнал, який минає за 1.6 с і
> означає невдалу операцію з чипом, а два спалахи з паузою тримаються
> **постійно**, доки блок живлення не в порядку. Сплутати їх означало б
> прийняти відсутній блок живлення за невдале читання пам'яті.
> Розшифровка — «`!`» перед номером сторінки на екрані (видно з будь-якої
> сторінки) і повний текст із числами на сторінці заряду, у вебі та в
> USB-клієнті. Пороги: немає `< 6 В`, занижено `< 12.5 В`, завищено `> 16 В`.

> 🔇 **ЗВУК ЗАРАЗ ВИМКНЕНО** — `BUZZER_DAC_PIN` закоментовано в `settings.h`
> (пін віддано керованому заряду). Прошивка від цього не страждає: `buzzer.h`
> має «тиху» гілку, налаштування й перелік сигналів усе одно доступні в API.
> Щоб повернути — розкоментуйте рядок, GPIO 25 вільний.

**🔊 Звук** (`BUZZER_DAC_PIN`, GPIO 25, пасивний п'єзо через розв'язувальний
конденсатор): **клац** при перегортанні меню + **м'які мелодійні** сигнали
операцій (початок — E5→A5, успіх — G5→B5→D6, помилка — A4→E4). Кожна нота з
огинаючою, гучність — `BUZZER_VOLUME` 0..255 (типово 150). Характер звуку
правиться на ходу (веб/USB → «Ремонт» → «🔊 Налаштування звуку») і живе в
SPIFFS. ⚠️ ЦАП — лише GPIO 25/26; динамік — тільки через підсилювач.

**💡 Підсвітка кнопок** (`BTN_LED_PIN`, необов'язково): рівне світіння у спокої,
блимання під час читання/запису/помилки — як індикатор роботи. `BTN_LED_ACTIVE_LOW`
— для модулів із загальним анодом.

## 9. Одиниці вимірювання

- **Лічильники заряду — у мА·год:** `мА·год = регістр × 0.4882 / Rsense`.
  Резистор струму: `settings.h → DS2438_RSENSE_OHM` (за замовч. 0.025 Ом) —
  підберіть, щоб ємність сходилась з паспортною (типово 20…40 мОм).
- **Цикли:** 1 цикл = сумарний заряд (розряд), рівний одній повній
  паспортній ємності. Ємність АКБ: `settings.h → BATTERY_RATED_MAH`
  (за замовч. 2500; PMNN4409 — 2500, PMNN4493 — 3000).
- **Заряд, %:** пріоритет ICA (якщо DS2438 рахує струм, IAD=1), інакше
  оцінка за напругою (`BATTERY_EMPTY_MV`…`BATTERY_FULL_MV`).

## 10. Формат прошивки IMPRES (за аналізом дампів)

- **Контрольна сума заголовка DS2433:** `сума 0x00..0x1F ≡ 0x41`
  (байт 0x1F — контрольний).
- **Контрольна сума TLV-записів:** сума байт запису разом з її контрольним
  байтом `≡ 0x5A` (напр. запис історії ємності 0x17).
- **Дзеркало калібрування:** `DS2438[24:50] == DS2433[1:27]` на кожній
  справжній АКБ. Блок **однаковий для всіх батарей однієї моделі**
  (4488A і 4493A збігаються, 4409A відрізняється).
- **Модель** — в авторитетному записі `0x0B` (`0B 'P' ...`), а також
  дублюється як ASCII у заголовку.

**Прив'язки до серійного номера чипа НЕМАЄ.** Побайтове порівняння двох
батарей однієї моделі показує: усі відмінні байти — лічильники
використання/телеметрія; підпису від лазерного ROM DS2438 у даних немає.
Прошивка прив'язана до **МОДЕЛІ**, тому відновлення можливе з еталона тієї
ж моделі без підбору серійника.

## 11. Типові сценарії

**Відновити повністю стерту АКБ (DS2433 = нулі, DS2438 цілий):**
запишіть `.bin` еталонної батареї тієї ж моделі (вкладка «Прошивка» →
«Запис/відновлення»), потім «🛠 Ремонт цілісності» — він синхронізує дзеркало
з уцілілого DS2438 цієї батареї.

**Пошкоджений заголовок/калібрування (рація «не бачить»):**
«🛠 Ремонт цілісності» — перерахує суми і відновить дзеркало.

**Оригінал «невідомий» або не вмикається:** якщо суми/дзеркало в нормі —
проблема не в прошивці, а в елементах (розряджені/мертві) або потрібне
калібрування на IMPRES-ЗП. Спробуйте «♻️ Скидання для рекалібрування».

**Клон з обнуленим DS2438** (напр. PT4409A): рація відхиляє через відсутність
калібрування; повне відновлення потребує еталонного DS2438 тієї ж моделі.

**Змінити показник ємності:** «🔋 Змінити ємність» → введіть % → запис.

**Точкова правка будь-якого байта:** «✏️ Редактор байтів» → «Завантажити» →
правка → «Записати байти» (з увімкненим автовиправленням сум).

> ⚠️ **Автоматична «розлочка» без еталона неможлива** — калібрувальні дані
> унікальні для моделі й не виводяться математично. Перед будь-яким записом
> робіть резервну копію.

## 13. Робота по USB (Windows-клієнт)

Пристрій дублює весь функціонал вебу через **USB-кабель** (той самий, яким
прошиваєте). Працює **паралельно** з Wi-Fi.

**Клієнт — `client_usb.html`** (Web Serial):
1. Відкрийте `client_usb.html` у **Chrome** або **Edge**.
   - Якщо сторінка пише, що Web Serial недоступний з `file://`, покладіть файл
     у теку і запустіть `python -m http.server`, відкрийте
     `http://localhost:8000/client_usb.html`.
2. Натисніть **«Підключити»** → оберіть COM-порт ESP32 (той самий, що в
   Arduino IDE). Зачекайте ~1.5 с (ESP32 перезавантажується при відкритті
   порту — це нормально).
3. Далі — той самий інтерфейс, що у вебі: вкладки Огляд / Дані / Прошивка,
   зчитування, дампи, запис, скидання, ремонт, зміна ємності, редактор байтів.

**Протокол** (`serial_api.h`, 115200 бод) — текстові команди, відповідь одним
рядком `#R#{json}`; підходить і для власного клієнта (Python/C#):

| Команда | Дія |
|---|---|
| `PING` | ідентифікація (`ver`, `authed`) |
| `READ` | зчитати обидві мікросхеми |
| `INFO` | усі декодовані поля + дампи (hex) |
| `GET33` / `GET38` | сирий дамп (hex) |
| `WRITE33 <hex>` / `WRITE38 <hex>` | запис дампа (як є) |
| `WRITEFIX33 <hex>` | запис DS2433 + автопочинка суми/дзеркала |
| `RESET` / `REPAIR` / `CLEAN` | скидання / ремонт / очистка |
| `WIPE33` / `WIPE38` | повне стирання DS2433 / DS2438 |
| `RECAL` | підготовка до рекалібрування (рецепт після заміни елементів) |
| `SETCAP <0..100>` / `SETMAH <мА·год>` | ємність % / залишкова ємність |
| `SETCHG <0..100>` | заряд % (ICA); при застряглому паливомірі — за напругою |
| `SETMODEL <NAME>` | ручний запис моделі (3..9 символів `A–Z 0–9`) |
| `SETETM <сек>` | ETM (наробіток) |
| `TEMPLATES` | список вшитих моделей-еталонів |
| `INITBAT <MODEL> <мАг>` | ініціалізувати порожній чип як новий АКБ моделі |
| `RESTORE <MODEL>` | відновити еталон **verbatim** |
| `WIZARD` / `WIZSTEP <idx> [MODEL]` / `WIZRESET` | Майстер: аналіз / крок / скидання |
| `WIZLIST` / `WIZDEL <serial>` | список / видалення журналів відновлення |
| `AUTH` | *(історична)* завжди «ОК» — пароль прибрано |
| `REBOOT` | перезавантаження ESP32 |

> 🔓 **Пароль прибрано** — і по USB, і у веб-API операції доступні напряму.
> `AUTH` лишено для сумісності (повертає «ОК»).
> Відладкові рядки у Serial не мають префікса `#R#` — клієнт їх ігнорує.
