# NTR Phone — разблокировка галереи

Одна страница, `index.html`, которая открывает всё содержимое галереи прямо в
файле бэкапа `.ntrbckp`. Внешних библиотек нет, сервер не нужен: можно открыть
файл двойным щелчком, всё считается в браузере и никуда не отправляется.

Сделано по бэкапу сборки **0.45.0 [079cfe9]**.

## Как пользоваться

1. В игре: **Phone → Settings → Backup → Export**. Сохраните файл и, прежде чем
   что-то делать, **отложите копию** — это точка отката.
2. Откройте `index.html` и перетащите в него `.ntrbckp`.
3. Выберите, откуда брать полный список файлов (см. ниже), при желании снимите
   галочку с разблокировки контактов.
4. **Скачать разблокированный бэкап** → в игре **Backup → Import**.

## Откуда берётся список файлов

Игра хранит в сохранении только пути к уже открытым файлам, а не полный
перечень. Поэтому источника три:

| Источник | Точность | Когда |
|---|---|---|
| Встроенный каталог 0.45.0 | 690 записей | По умолчанию, файлы игры не нужны |
| `.pck` / `.exe` / `.apk` игры | точно, любая версия | Лучший вариант |
| Папка с ассетами | точно | Распакованные сборки |

Встроенный каталог собран из полного прохождения 0.45.0: он покрывает всё, что
там есть, включая четырнадцать пропусков в нумерации (`Amber16`…`Amber22`,
`Lilith25`, `Lilith54`, `Mabel2`, `Mabel3`, `Naomi16`, `Polly14`, `Rachel63`).
Контента, добавленного после 0.45.0, он не знает — для новых версий берите
список из `.pck`.

Из `.pck` читается **только оглавление** — имена файлов; сами ассеты не
распаковываются. Понимает отдельный `.pck`, пак, вшитый в `.exe`, и `.pck`
внутри `.apk`. Зашифрованное оглавление прочитать нельзя — страница честно об
этом скажет.

«Расширить каждую серию на N файлов» — догадка для нового контента: дописать
`Rachel103`, `Rachel104` и так далее. Несуществующие пути игра просто не
покажет, но и пользы от них нет, поэтому по умолчанию 0.

## Что меняется в бэкапе

Архив пересобирается целиком, но имена, порядок, даты и атрибуты записей
сохраняются, а содержимое меняется только у тех файлов, которые правятся:

- `virtualphone/gallery/unlocked_photos` — дописываются недостающие записи
  `{character, filepath, timestamp, type}` (тип: 0 фото, 1 аудио, 2 видео);
- `virtualphone/messenger/contacts_list` — `locked` → `unlocked`, если галочка
  стоит (без этого часть галереи не на что повесить). Служебные `dev-locked`
  трогаются только по отдельной галочке;
- `virtualphone/tracker/completion_cache` — по желанию, все счётчики в 100.

`persistent_data` не трогается вовсе: `is_patron` и `user_patron_code` — это
платная подписка, а не прогресс, и инструмент их не подделывает.

## Проверка

```sh
python3 ntr_gallery/selftest.py                    # на синтетическом бэкапе
python3 ntr_gallery/selftest.py путь/к/бэкапу.ntrbckp
```

Скрипт вытаскивает встроенный `<script>` из `index.html` и гоняет **тот же
код**, что работает в браузере, под node (нужен v18+ ради
`CompressionStream`): читает бэкап, раскрывает каталог, строит план, собирает
новый архив и проверяет, что его принимает штатный `zipfile` и что внутри
ровно то, что обещано. Отдельно проверяются нули впереди в номерах
(`Rachel01`, но `Rachel102` — на этом легко ошибиться) и разбор оглавления
`.pck` обеих версий формата, включая вшитый в `.exe`.
